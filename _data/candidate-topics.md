## 🔴 A. 실전 개발 — 아직 없는 필수 지식

| # | 토픽 | 왜 중요한가 |
|---|------|-----------|
| A1 | **SWE + UGAP 동시 게이팅 패턴** — 두 모드에서 공통으로 동작해야 하는 기능의 올바른 ESMain 호출 패턴 | 게이팅 누락이 임상 데이터 오염 |
| A2 | **복합 구조체 원자 교체** — ROI x/y/width/height 4개를 Render↔SetParameter 스레드 간 원자적으로 교체하는 패턴 | 단일 float은 atomic으로 해결되지만 구조체는 방법이 없음 |
| A3 | **OVObject Active 상태 확인법** — "내 Render()가 불리고 있는지" 디버거/로그로 확인하는 구체적 방법 | OnActivate 안 불린 채 Render 기다리는 삽질 |
| A4 | **void 콜백에서 오류 전파** — bool 반환 없는 OnNewFrame/SetParameter에서 오류를 상위 레이어로 전달하는 방법 | bool+out-param 패턴만 있고 void 콜백 오류 처리는 공백 |
| A5 | **enum 값 추가 시 영향 범위 grep** — AcqAssistState에 새 값 추가 시 switch 문 빠진 곳 자동으로 찾는 절차 | enum 추가 → 런타임 undefined behavior가 조용히 발생 |
| A6 | **ESMain.cpp PR 리뷰 체크리스트** — 리뷰어 관점에서 무엇을 봐야 하는지 (작성자 관점과 다름) | 리뷰 방법 없음 → 게이팅 누락이 코드리뷰에서 안 잡힘 |
| A7 | **새 탄성 모드(예: cSWE) 추가 완전 체크리스트** — enum, 팩토리, GC 키, 게이팅, DICOM 코드까지 7개 수정 지점 | add-new-ovobject.md보다 훨씬 광범위한 변경 필요 |
| A8 | **Deactivate→Reactivate 후 파라미터 재등록 필요 여부** — 모드 전환 반복 시 기존 SetParameter 수신이 살아있는지 | 조용한 파라미터 손실 → 임상 중 재현 불가 버그 |

## 🟠 B. 디버깅 & 진단 — 막혔을 때 꺼내는 것

| # | 토픽 | 왜 중요한가 |
|---|------|-----------|
| B1 | **Debug 되고 Release 안 되는 버그 조사 절차** — 최적화로 인한 UB, volatile 누락, 메모리 레이아웃 차이 단계별 진단 | 가장 흔한 유형의 "재현 불가" 버그 |
| B2 | **GC 파라미터 묵음 드롭 운영 환경 감지** — 운영(Release) 환경에서 키 오타/버전 불일치로 드롭됐을 때 감지 메커니즘 | 개발 중엔 로그로 찾지만 운영 중엔 방법이 없음 |
| B3 | **프레임 오버런 처리 방식** — Acquisition 스레드가 처리 중일 때 새 프레임 도착 시 큐잉 vs 드롭 vs 교체 메커니즘 | 고부하 상황에서 데이터 유실 또는 메모리 증가 원인 |
| B4 | **현장 minidump ↔ PDB ↔ git 커밋 매핑법** — 릴리즈 빌드 바이너리와 소스를 대응시켜 크래시 원인 찾는 절차 | crash-dump-analysis.md에 빠진 핵심 단계 |
| B5 | **OVObject dynamic_cast nullptr 진단 순서** — 팩토리 등록했는데 cast 실패할 때 3단계 중 어디가 문제인지 찾는 법 | add-new-ovobject.md에서 실패 경로 진단 없음 |
| B6 | **GrandCentral 상태 의존 코드 단위 테스트 격리** — GC가 없는 테스트 환경에서 UDT 의존 함수를 테스트하는 seam 패턴 | mock 아티클은 있지만 GC 자체 격리 방법이 없음 |
| B7 | **Variant 타입 불일치 사전 검증** — 발행측(Layer A)과 수신측(Layer B)의 Variant 타입이 다를 때 프리프로덕션에서 잡는 법 | silent failure → 운영 중 발견 |

## 🟡 C. 아키텍처 심화 — "왜 이렇게 동작하나"

| # | 토픽 | 왜 중요한가 |
|---|------|-----------|
| C1 | **GC 파라미터 버스 동시 발행 ordering** — UI 스레드와 Acquisition 스레드가 같은 키를 동시에 발행하면 어느 값이 이기는가 | 동시 발행 시 데이터 정합성 보증 여부 불명 |
| C2 | **OnDeactivate 중 Render() 직렬화 보증** — GrandCentral이 두 콜백을 직렬화하는지, IsValid()만으로 충분한 이유 | IsValid() 패턴의 실제 안전 근거가 없음 |
| C3 | **모드 전환 중 게이팅 술어 전환 찰나** — InElasto/IsInUGAPMode가 둘 다 false인 전환 구간에 이벤트가 오면 어떻게 되나 | 전환 구간 이벤트 손실 가능성 |
| C4 | **FrontPanel 이벤트 큐 백프레셔** — 사용자 입력이 ESMain 처리보다 빠를 때 드롭 정책이 drop-oldest인지 drop-newest인지 | 빠른 노브 조작 시 이벤트 손실 여부 |
| C5 | **COM과 GC 파라미터 버스 상호작용** — COM 이벤트가 GC 버스를 트리거하는 경로가 있는지, 완전 독립인지 | COM 코드 건드릴 때 GC 영향 범위 불명 |
| C6 | **RunPeriodic 작업 셧다운 드레이닝** — ScCommon::Thread::RunPeriodic으로 등록된 작업이 실행 중일 때 Shutdown()이 완료를 기다리는지 | 셧다운 중 작업자 스레드 충돌 가능성 |

## 🟢 D. 도메인 & 규제

| # | 토픽 | 왜 중요한가 |
|---|------|-----------|
| D1 | **프로브별 동작 분기 코드 위치** — "Probe A는 되고 Probe B는 안 된다" 버그 조사 시 코드 분기점 찾는 법 | 프로브 종류별 preset 로딩과 코드 분기 전혀 설명 없음 |
| D2 | **AuditLog 의무 vs 선택 판단 기준** — 어떤 사용자 이벤트가 FDA 기록 의무인지 결정하는 실무 기준 | 코드 리뷰에서 AuditLog 누락 잡기 어려움 |
| D3 | **IEC 62304 변경 제어 실무 절차** — 코드 변경 후 어떤 설계 문서를 개정하고 어떤 승인이 필요한지 단계별 | 신규 개발자가 규제 절차 건너뛰는 가장 흔한 실수 |
| D4 | **LiverAI 추론 스레드 모델** — AI 모델 추론이 렌더 스레드와 별도 스레드에서 도는지, 예상 레이턴시가 16ms 예산에 맞는지 | AI 추론 결과가 렌더를 블로킹하는지 불명 |
| D5 | **FatalErrorHandler 후 데이터 flush 보증** — 크래시 직전 버퍼에 있는 DICOM SR과 감사 로그가 저장되는지 | 환자 데이터 유실 가능성 |
| D6 | **SWE 임상 측정 집계 방식** — Freeze 중 ROI 고정 후 10회 중앙값 취득이 코드에 구현돼 있는지, EFSUMB 가이드라인과 연결 | 임상 신뢰도 지침과 코드 연결이 끊겨 있음 |
| D7 | **AcqAssistState 버전 불일치 방어 패턴** — Layer A/B가 서로 다른 버전의 enum을 쓸 때 Layer B가 미지의 정수를 받으면 어떻게 처리해야 하나 | 레이어 독립 배포 환경에서 현실적 위험 |
