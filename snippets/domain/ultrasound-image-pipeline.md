RF 신호에서 화면 출력까지 5단계 파이프라인을 이해한다.

## Why

gipc-app 코드를 수정할 때 어떤 레이어가 어떤 단계를 담당하는지 알아야 버그 위치를 잘못 짚지 않는다.
예: 영상이 흐리면 빔포밍 문제인지 스캔 변환 문제인지 먼저 구분해야 한다.

## Pattern

```
┌─────────────────────────────────────────────────────────────────────┐
│                     초음파 영상 처리 파이프라인                      │
└─────────────────────────────────────────────────────────────────────┘

  [트랜스듀서]
       │  RF(Radio Frequency) 신호 — 수십 MHz 아날로그
       ▼
  ① 빔포밍 (Beamforming)
  ┌──────────────────────────────────────────┐
  │  채널별 지연(delay) + 합산(sum)           │
  │  → 특정 초점 방향의 에코 신호 합성        │
  │  담당: FPGA / DSP (하드웨어)              │
  └──────────────────────────────────────────┘
       │  IQ(In-phase/Quadrature) 데이터
       ▼
  ② 엔벨로프 검출 (Envelope Detection)
  ┌──────────────────────────────────────────┐
  │  복소 IQ → 크기(magnitude) 추출          │
  │  = sqrt(I² + Q²)                         │
  │  담당: DSP / EchoScanner                  │
  └──────────────────────────────────────────┘
       │  Polar 좌표 영상 데이터 (스캔라인 배열)
       ▼
  ③ 로그 압축 (Log Compression)
  ┌──────────────────────────────────────────┐
  │  인체 조직 반사 강도 차이 = 수십 dB     │
  │  log() 스케일로 압축 → 동적 범위 축소   │
  │  담당: EchoScanner                        │
  └──────────────────────────────────────────┘
       │  Polar 좌표, 8-bit 밝기값
       ▼
  ④ 스캔 변환 (Scan Conversion)             ◀── 가장 무거운 단계
  ┌──────────────────────────────────────────┐
  │  Polar (r, θ) → Cartesian (x, y)        │
  │  보간(interpolation)으로 직사각형 픽셀   │
  │  격자에 매핑                             │
  │  담당: GPU / DSP (CPU로 하면 프레임 드롭)│
  └──────────────────────────────────────────┘
       │  Cartesian 픽셀 버퍼 (Frame)
       ▼
  ⑤ 디스플레이 / 오버레이 합성
  ┌──────────────────────────────────────────┐
  │  측정선, 캘리퍼, 레이블 등 OV 오버레이  │
  │  화면 출력 (GDI / OpenGL)               │
  │  담당: GcViewer, OVObject 계층구조       │
  └──────────────────────────────────────────┘
       │
  [모니터 / 임상의]
```

**gipc-app 레이어 매핑**

| 단계 | 담당 레이어 |
|------|------------|
| ①② 빔포밍 + 엔벨로프 | 하드웨어 드라이버 + `EchoScanner` |
| ③ 로그 압축 | `EchoScanner` (SW) 또는 DSP |
| ④ 스캔 변환 | GPU 셰이더 또는 DSP 오프로드 |
| ⑤ 디스플레이 | `GcViewer` + `OVObject` 렌더링 |

## Key Points

- 스캔 변환을 CPU로 처리하면 1280×1024 해상도에서 프레임당 ~30 ms 소요 → 30 fps 유지 불가. GPU 또는 DSP 오프로드가 필수
- `EchoScanner`는 ①~③의 SW 래퍼 역할; 하드웨어 완료 콜백을 받아 `Frame`을 조립하여 큐에 전달
- `GcViewer`는 ⑤만 담당. 픽셀 연산 없음; 이미 완성된 `Frame`을 받아 화면에 올림
- Polar→Cartesian 보간 방법(최근접/쌍선형/바이큐빅)은 영상 품질 vs 처리 속도 트레이드오프 — 임상 요건에 따라 선택
- B-mode(밝기) 외에 Doppler(혈류 속도), M-mode(시간축 운동), Elastography 등 모드마다 파이프라인 변형이 있음
